# Dikidi-помощник — навык для Яндекс Алисы

Голосовой навык: «Добавь запись» запускает диалог сбора данных (имя, телефон,
услуга, дата, время) и создаёт запись в Dikidi; «Сколько записей на сегодня»
озвучивает количество и время записей.

## Подключение к Dikidi

У Dikidi нет публичного API, поэтому бекенд выбирается через
`DIKIDI_BACKEND` (см. `.env.example`):

| Значение | Что делает | Когда использовать |
| --- | --- | --- |
| `mock` | in-memory заглушка, ничего не создаёт | разработка и тесты |
| `sdk` | вход по телефону и паролю через `dikidi-api-client` | рабочий вариант сейчас |
| `http` | официальный API по токену | когда Dikidi выдаст доступ |

### Вариант `sdk` (вход по телефону и паролю)

1. Скопируйте `.env.example` в `.env`, заполните `DIKIDI_PHONE`,
   `DIKIDI_PASSWORD`, `DIKIDI_COMPANY_ID` (id компании виден в адресной
   строке кабинета: `?company=1400000`) и поставьте `DIKIDI_BACKEND=sdk`.
2. Проверьте связь, ничего при этом не создавая:
   ```powershell
   .venv\Scripts\python.exe scripts\check_dikidi.py
   ```
   Скрипт напечатает ваши услуги, мастеров и записи на сегодня. Оттуда же
   возьмите id мастера для `DIKIDI_DEFAULT_STAFF_ID` (если не задать —
   возьмётся первый из каталога).

**О чём важно знать.** `dikidi-api-client` — неофициальный пакет, который
логинится как браузер и ходит по веб-шлюзам CRM. Версия закреплена
(`==0.1.3`) намеренно: публичного репозитория у пакета нет, код этой версии
проверен вручную — учётные данные уходят только на домены `dikidi.ru` и
`dikidi.net`. Обновлять версию стоит только после повторной проверки
исходников. Dikidi может поменять вёрстку — тогда вызовы отвалятся, и навык
скажет «Не могу сейчас связаться с Dikidi» вместо падения. Пароль даёт полный
доступ к аккаунту, поэтому держите его только в переменных окружения
(`.env` в `.gitignore`, на Render — в разделе Environment).

### Вариант `http` (официальный API)

Запросите у поддержки/личного менеджера Dikidi Business токен и спецификацию
эндпоинтов (Настройки → Интеграция → Доступ к API → «Добавить доступ», тип
доступа «администратор»), заполните `TODO` в `app/dikidi/http_client.py`,
пропишите `DIKIDI_TOKEN` и поставьте `DIKIDI_BACKEND=http`.

## Структура проекта

```
app/
  main.py              # FastAPI, POST /alice/webhook
  config.py            # настройки из .env
  alice/
    models.py          # pydantic-модели протокола Яндекс Диалогов
    nlu.py             # извлечение имени/телефона/услуги/даты/времени
    router.py           # определение интента и диспетчеризация
    scenarios/
      add_booking.py    # слот-филлинг для создания записи
      today_bookings.py # сводка записей на дату
  dikidi/
    client.py           # интерфейс DikidiClient + выбор бекенда
    mock_client.py       # in-memory реализация для разработки/тестов
    sdk_client.py         # вход по телефону и паролю (dikidi-api-client)
    http_client.py        # заготовка официального API (нужны токен и доки Dikidi)
tests/                   # pytest: nlu, сценарии, SDK-маппинг, вебхук целиком
deploy/                  # systemd unit + пример конфига nginx для VPS
render.yaml              # деплой на Render
scripts/
  send_test_request.py    # ручная прогонка диалога по HTTP без Алисы
  check_dikidi.py         # проверка связи с реальным Dikidi (только чтение)
```

## Локальный запуск и тесты

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest

# Поднять вебхук локально:
.venv\Scripts\python.exe -m uvicorn app.main:app --reload

# В другом терминале — прогнать диалог целиком:
.venv\Scripts\python.exe scripts\send_test_request.py
```

## Как это станет настоящим навыком Алисы

1. **Домен + HTTPS на VPS.** Яндекс Диалоги принимают вебхук только по HTTPS
   с валидным сертификатом. Получите сертификат (например, через certbot) на
   своём VPS и настройте nginx по примеру `deploy/nginx.conf.example` —
   прокси на `127.0.0.1:8000`, где крутится приложение.
2. **Запуск приложения как сервиса.** Скопируйте проект на VPS (например, в
   `/opt/dikidi-alice-skill`), создайте `.venv`, установите зависимости,
   заполните `.env` (на основе `.env.example`), используйте
   `deploy/dikidi-alice.service` как шаблон systemd unit (поправьте пути и
   пользователя под свой сервер), затем:
   ```bash
   sudo systemctl enable --now dikidi-alice
   ```
3. **Регистрация навыка.** В https://dialogs.yandex.ru/developer/ создайте
   навык, в настройках укажите URL вебхука
   (`https://ваш-домен/alice/webhook`). Отдельная NLU-модель/формы в
   консоли не нужны — весь разбор реплик делает сам код.
4. **Проверка.** В консоли есть тестовый стенд с голосовым/текстовым вводом —
   прогоните тот же диалог, что в `scripts/send_test_request.py`.

## Известные ограничения MVP

- **Выбор мастера не озвучивается** — используется один `DIKIDI_DEFAULT_STAFF_ID`
  из конфига. Если у клиента несколько мастеров и это важно — нужно добавить
  отдельный шаг в диалог.
- **Извлечение имени** — упрощённая эвристика (первое похожее на имя слово).
  Для сложных случаев (составные имена, несклоняемые формы) можно поправить
  записанное имя командой «исправить имя» прямо в диалоге.
- **Подбор услуги** — нечёткое сопоставление по названию из Dikidi. Если
  произнесённое не нашлось, навык скажет об этом и перечислит доступные
  услуги. При большом количестве похожих названий порог совпадения в
  `app/alice/nlu.py` (`SERVICE_MATCH_THRESHOLD`) может потребовать подстройки.
- **Несколько услуг в записи** — собираются по одной, пока не скажете «всё»
  («хватит», «готово», «стоп»). Как Dikidi принимает несколько услуг в одной
  записи, проверено только на уровне `service_ids` — если в вашем аккаунте
  поведение отличается, правится в `app/dikidi/sdk_client.py`.
- Определение интента («добавь запись» / «сколько записей») — по ключевым
  словам, без форм Яндекса. Для более гибкого распознавания в будущем можно
  подключить NLU-модель в консоли Диалогов.
- **На бесплатном плане Render** сервис засыпает после 15 минут простоя, а в
  режиме `sdk` после пробуждения заново логинится в Dikidi (файл сессии на
  Render не сохраняется). Первый запрос после простоя может быть медленным.

## Подключение через страницу и проверка озвучки

Для одного салона задайте в Render → Environment:

- `DIKIDI_BACKEND=sdk` (в режиме `mock` реальные записи не создаются);
- `PUBLIC_BASE_URL=https://dkdialice.onrender.com`;
- `ALICE_OWNER_ID` — значение `session.user.user_id` из запроса вашего аккаунта Алисы
  (если `session.user` отсутствует, используйте `session.user_id`).

После деплоя скажите «настройка», откройте кнопку и заполните `/setup`:
одноразовый код, телефон, пароль, ID компании и ID мастера. Страница проверяет
каталог и наличие мастера перед сохранением. Код действует 10 минут и используется
один раз; после ошибки проверки получите новый. Пароль не возвращается в ответе страницы.

Привязка в памяти исчезает после перезапуска. Для постоянной настройки заполните
`DIKIDI_PHONE`, `DIKIDI_PASSWORD`, `DIKIDI_COMPANY_ID`, `DIKIDI_DEFAULT_STAFF_ID`
в Environment на Render. Не отправляйте пароль в чат или в репозиторий.

Запускайте один процесс uvicorn / один экземпляр сервиса: состояние диалогов,
привязки и ожидающие операции сейчас хранятся в памяти. Для нескольких экземпляров
нужны общая БД и очередь. Перезапуск во время сохранения требует проверки журнала
Dikidi перед повторной записью.

Вызов Dikidi выполняется в фоне: если он не закончен за две секунды, навык
просит сказать «проверить результат». Пока операция выполняется, новые реплики
проверяют её результат, а не запускают повторное сохранение. «Записал» произносится
только после проверки ID и телефона клиента в журнале. Если результат неизвестен,
проверьте журнал вручную перед новой попыткой. Сон бесплатного Render всё ещё может
задержать самый первый запрос до запуска Python; обработчик этого устранить не может.

Команда «проверка звука» возвращает короткий ответ с `tts` без обращения к Dikidi.
В приложении Алисы задавайте вопрос голосом: на ввод с клавиатуры приложение может
отвечать только текстом. Проверяйте также громкость мультимедиа и подключённые наушники.
Справка: https://alice.yandex.ru/support/ru/assistant/faq
