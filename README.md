# Dikidi-помощник для Алисы

«Добавь запись» собирает имя, телефон, процедуры, дату и время. Скажите «всё»,
чтобы завершить список процедур. «Сколько записей сегодня» читает журнал DIKIDI.

## Подключение пользователем

1. Откройте навык и нажмите **Подключить DIKIDI** (либо скажите «настройка»).
2. Введите **телефон и пароль DIKIDI Business**. Код и технические ID не нужны.
3. Если доступен один салон и один мастер, они выбираются автоматически.
   При нескольких вариантах выберите название салона и имя мастера из списка.
4. Вернитесь в Алису и скажите «добавь запись».

Подключение автоматически закрепляется за аккаунтом Алисы, открывшим ссылку.
Первый успешный вход назначает владельца единственного салона этого экземпляра
навыка. Другой пользователь не может заменить подключение или читать его записи.
Для первоначальной привязки используйте свой приватный/тестовый навык.

Ссылка одноразовая, действует 10 минут. Код передаётся во фрагменте ссылки,
не в URL запроса сервера. Браузер получает HttpOnly Secure cookie, формы защищены
CSRF-токеном. При истечении ссылки скажите «настройка» ещё раз.

Телефон, пароль, выбранные компания/мастер и владелец сохраняются в базе
в зашифрованном виде (Fernet). Ключ находится отдельно в окружении сервера.
После перезапуска подключаться заново не нужно, если база и ключ сохранены.

## Однократная настройка Render администратором

Для существующего https://dkdialice.onrender.com:

1. Создайте PostgreSQL в том же регионе, что и web service. Можно применить
   Blueprint **deploy/render-database.yaml** через New → Blueprint, указав этот
   путь. Он создаёт только базу и не дублирует существующий web service.
2. В существующем web service → Environment задайте:
   - `DATABASE_URL` — **Internal Database URL** созданной базы;
   - `CREDENTIALS_ENCRYPTION_KEY` — случайный секрет, минимум 32 символа;
   - `PUBLIC_BASE_URL=https://dkdialice.onrender.com`;
   - `DIKIDI_BACKEND=sdk`.
3. Ключ можно сгенерировать локально:
   ```powershell
   .venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
   ```
   Сохраните его в Render и резервной копии. Не присылайте в чат, не коммитьте.
   Не генерируйте новый ключ при каждом деплое: старые данные станут нечитаемыми.
4. Старые `ALICE_OWNER_ID`, `DIKIDI_PHONE`, `DIKIDI_PASSWORD`,
   `DIKIDI_COMPANY_ID`, `DIKIDI_DEFAULT_STAFF_ID` для новой привязки не нужны.
   Если переходите с прежней настройки, удалите их из Environment перед входом.
5. Выполните Save and deploy. Таблица создаётся приложением автоматически.
   После этого пройдите подключение через навык.

Для нового развёртывания `render.yaml` описывает сервис и базу вместе,
подставляет DATABASE_URL и генерирует ключ автоматически.

**Тариф базы:** в примерах выбран Free для тестов. Free PostgreSQL Render
истекает через 30 дней; для постоянной работы нужен тариф без этого ограничения.
Платные ресурсы код сам не создаёт.
https://render.com/docs/free

Без DATABASE_URL и ключа навык сообщает, что хранилище не настроено;
он не выдаёт временное сохранение в памяти за постоянное подключение.

## Проверка и ограничения

- SDK `dikidi-api-client==0.1.3` неофициальный. Вход работает через веб-шлюзы DIKIDI.
  Список компаний читается из ссылок `company=...` в навигации авторизованного
  кабинета; это не документированный метод SDK. Тесты используют HTML-фикстуры,
  реальный аккаунт ещё нужно проверить. Если DIKIDI изменил страницу или выводит
  компании только через JavaScript, подключение покажет ошибку, не выберет случайный ID.
- Мастер выбирается при подключении; голосовой выбор мастера на каждый визит пока отсутствует.
- Долгие операции выполняются в фоне. По просьбе Алисы скажите «проверить результат».
  Успех сохранения проверяется по ID и телефону в журнале; при неопределённом
  результате проверьте журнал вручную перед новой попыткой.
- Один экземпляр сервиса / один процесс uvicorn: диалог, ссылки подключения и
  ожидающие операции пока в памяти, постоянное подключение — в базе.
- Бесплатный Render засыпает и может не успеть ответить на первый запрос Алисы.
- «Проверка звука» возвращает `tts` без DIKIDI. В приложении задавайте вопрос
  голосом: текстовый ввод обычно получает письменный ответ.
  https://alice.yandex.ru/support/ru/assistant/faq

## Разработка

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pytest -q
.venv\Scripts\python.exe -m uvicorn app.main:app --reload
```

По умолчанию `DIKIDI_BACKEND=mock` — демонстрация без реальных записей.
Для локальной постоянной базы можно задать `DATABASE_URL=sqlite:///connections.db`
и постоянный ключ. SQLite на эфемерном диске Render использовать нельзя.
Вебхук: `POST /alice/webhook`, страница подключения: `GET /setup`.
Пустой GET /setup предлагает открыть ссылку из Алисы, а не привязывает случайного пользователя.

Старый режим `http` остаётся заготовкой для официального API. Переменные
DIKIDI_PHONE/PASSWORD/COMPANY_ID поддерживаются для миграции и read-only пробника
`scripts/check_dikidi.py`, но обычному пользователю они больше не нужны.
